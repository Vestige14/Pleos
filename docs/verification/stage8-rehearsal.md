> 과거 회차 기록이다. STT 누락 수정·실제 녹음 재확인과 소스 릴리즈의 최신 수락 범위는 [v0.1.0 안내](../releases/v0.1.0.md)를 우선한다. 아래 실패·보류 결과는 당시 관측으로 보존한다.

## 2026-11-15 사용자 결정: 내비 데모 대안과 개선 판단

- 실제 내비 도착 이벤트를 에뮬레이터에서 재현할 방법이 확보되지 않으면, **데모용 목적지 기록을 별도로 생성·준비하여 차후 영상 시나리오를 진행**한다. 칼국수집→해변→카페 자료와 연결하되 합성/사전 준비 기록임을 구분하고 기존 사용자 기록을 덮어쓰지 않는다.
- 목적지 기록은 목적지 설정/관측의 근거이며, 실제 SDK 도착 수신이나 방문 확정으로 위장하지 않는다. 실제 도착 수신·저장 공백과 이슈 #4는 유지한다. 데모 기록 생성 방식의 상세 구현은 아직 없으며 이번에는 방향만 기록한다.
- 촬영은 사용자 후속 요청 때 진행한다. 이 결정으로 지금 촬영·Release·push를 시작하지 않는다.
- API 개선 판단: 기억 연결 모델/추론 강도 상향은 비교 후보지만 REVIEW 원인은 미확정이다. 현 프롬프트의 보수적 모호성 정책 및 응답 검증도 REVIEW를 만들 수 있으므로 동일 입력의 모델 응답과 후처리를 구분해야 한다. 사진 단독 설명5건은 이미 성공해 우선 교체 근거가 없다.
- 날짜 문제는 Pleos ON_DEVICE STT가 11월을12월로 인식한 것과 로컬 날짜 규칙이 이를 전년도 날짜로 해석한 것이 결합했다. 기억 연결 API 모델만 바꿔 해결되지 않는다. 원음·STT 원문을 보존하면서 별도 경험 날짜 확인/보정 흐름을 우선 검토한다. 클라우드 STT는 음성 외부 전송 범위가 달라지므로 이번 API 질문을 전송 승인으로 해석하지 않는다.
- 다음 비교를 실행한다면 기존 입력을 고정해 현 설정·추론 강도 상향·상위 모델을 소수 대표 사례에서 비교한다. 다른 날짜 잘못 연결/근거없음까지 함께 보며 성공할 때까지 반복하거나 전체 리허설을 매번 돌리지 않는다. 이번에는 모델 변경·유료 호출·제품 코드 변경을 하지 않았다.

## 현재 판정

독립 자료로 3회 실행하고 실제 결과를 기록한 뒤 기대값과 비교했다. 기술적 실행 3회 종료를 시나리오 의미 수락 3회 성공으로 표시하지 않는다. **자동 연결을 포함한 매끄러운 데모·릴리즈 준비 완료는 아직 아니다.** 제품 코드는 변경하지 않았다. 촬영·Release·태그·원격 push는 하지 않았다.

## 확인한 범위와 한계

- 독립 비개발 자료 담당자가 사진7장·stock TTS3세트를 준비했다. 상세 기대값은 3회 결과 JSON의 SHA를 먼저 기록한 뒤 열람했다. 물리적으로 격리된 맹검을 주장하지 않는다.
- 실제 production PCM/STT·저장·후보/HTTP·Compose 검토·공유 렌더러를 사용하되 UUID 합성 DB와 사진을 시험에서 조립했다. 정상 런처부터 끝까지의 무주입 사용자 리허설은 아니다.
- 디지털 합성 PCM 입력이며 AudioRecord·사용자 마이크 시험이 아니다. PCM 동일성과 원문·DB 재열기 보존을 확인했고 이번 회차에서 사용자 청취나 강제종료 후 재생을 반복하지 않았다.
- 시험 날짜는 별도 메타데이터로 격리 Photo 행에 넣었다. 원본 PNG·EXIF를 수정하지 않았으며 실제 사진 스캐너 수집 검증을 대체하지 않는다.
- 사진 분석에는 이미지 자체만 전송했다. 사용자 개인 사진·음성·기록은 요청에 포함하지 않았다.
- 첫 회 PNG를 직접 확인했다. 칼국수집·해변 및 별도 공유 문장만 포함하고 카페·음성 원문·좌표는 포함하지 않았다. SHA256: `6fe09c79001b45ba0935a5814e5a19088653ef872f073cfe5d5c9387a5f041b8`. 이번 외부 chooser 전달은 실행하지 않았다.
- 실제 내비 정상 화면에서 북동삼거리손칼국수 대부도본점과 방아머리해수욕장을 검색·선택하고 경로 안내 화면을 확인했다. 도착이나 11월8일 방문을 입증한 것이 아니다. 실제 도착 미검증 [#4](https://github.com/chowonbhin/Pleos/issues/4)는 유지한다.
- 이번 3회 검토 UI에 NoRoot는 없었지만 기존 [#2](https://github.com/chowonbhin/Pleos/issues/2)를 해결했다고 주장하지 않는다.

## 결과 고정 후 수동 진행 확인

추가 API·STT 호출 없이 첫 회의 REVIEW_REQUIRED 기록에서 production 검토 화면의 직접 연결 수정·확정을 실행했다. 사용자 선택으로 CONFIRMED/USER가 됐고 STT 원문은 불변이었다. 이어 production 공유 화면에서 카페 제외·해변 사진1장 선택 해제·별도 공유 문장 입력·미리보기·뒤로/재진입·DB 재열기 보존을 확인했다. **1개 시험 PASS, 4.388초**. AI 제안 성공으로 합산하지 않는다.

시험이 첫 toggle을 명시적으로 선택한 것이므로 사람의 의미 판단 수락과는 다르다. 공유 방문 묶음은 합성 입력이며 AI가 생성한 방문 기록을 증명하지 않는다. 썸네일 제공자 없이 선택/미리보기 텍스트를 확인했고 내보내기 버튼은 이 후속에서 누르지 않았다. 실제 PNG 생성은 원래 첫 회의 별도 근거다.

초기 후속 시험은 JUnit 반환형 오류로 본문 실행 전 실패했다. 시험 반환형만 Unit으로 고친 뒤 실행했으며 최초 로그와 APK를 보존했다. 제품 수정이나 실패 assertion 완화는 없었다. 근거: `.local/stage8-rehearsal/manual-continuation-fixed-instrumentation.log`, `device-results/manual-continuation.json`.

## 환경 실패 기록

첫 사전 실행은 media/STT/API 전에 PARKED 대기 실패로 중단됐다. 실제 car_service 부재·CarService ANR/binder 부재와 정상 앱 UNKNOWN을 확인했다. 전용 에뮬레이터를 데이터 삭제 없이 정상 재부팅한 뒤 서비스와 P 상태가 복구돼 새 합성 배치로 3회를 진행했다. 영구 원인 해결이나 최초 실패 삭제로 처리하지 않는다.

ADB로 앱 외부 디렉터리 회수가 거부돼 해당 방식은 중단했다. 시험이 자신이 만든 합성 JSON/PNG만 Instrumentation status로 내보내도록 보완했다. root/run-as 또는 권한 우회는 사용하지 않았다.

## 다음 조치

자동 연결 REVIEW의 입력·판정 경계를 좁히고, 날짜 인식 오류에도 사용자가 경험 날짜를 바로잡아 진행할 수 있는 흐름을 확인해야 한다. STT 원문은 불변으로 유지한다. 합성 음성을 정답 대본으로 대체하거나 성공할 때까지 재시도하지 않는다. 새 제품 수정은 이 결과와 범위를 정한 뒤 진행한다. 촬영과 릴리즈 완료는 별도다.

Ruling: 격리된 합성 PCM과 production 구성요소로 3회를 실행 — 개인 자료 전송과 조율되지 않은 마이크 사용을 피하면서 승인된 합성 리허설 수행 — 정상 런처·AudioRecord 전체 경로 수락으로 확대할 위험이 있어 범위를 명시한다.

Ruling: 원본 사진 대신 sidecar 날짜를 시험 행에 주입 — 다른 경험 날짜의 연결 경계를 다루고 원본 보존 — 스캐너/EXIF 수집까지 통과한 것으로 오인하면 실제 유입 문제가 남으므로 별도 한계로 둔다.

Ruling: 실제 결과를 고정한 후 한 번의 수동 연결·공유 UI 후속 확인 — REVIEW 이후 사용자가 진행 가능한지 확인 — 수동 결과가 AI 성공으로 오인되지 않도록 원래 결과와 분리한다.

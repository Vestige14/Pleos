# v0.1.0 — 로컬 실행용 소스 릴리즈

2026-11-15. 사용자가 서버 배포·APK 제작 없이 Git에 사용 가능한 소스 버전을 올리도록 승인했다. `release/v0.1.0` 브랜치와 `v0.1.0` 태그를 같은 최종 통합 커밋에 둔다. 검증된 제품 소스는 `ce6780a`이며 이후 변경은 문서뿐이다. GitHub Release 페이지나 APK 첨부는 이번 게시 범위가 아니다.

## 포함 범위

- 원본 음성·불변 STT·선택적 위치 저장, 재시작 후 기록 확인.
- 사진 후보 연결·해제, 사진 단독 설명과 시간 근거 기반 기억 연결, 사용자 확인·수정·거절·해제.
- 선택한 내용만 공유 초안·미리보기·PNG에 포함하고 시스템 공유창으로 전달.
- STT의 첫 구절 조기 종료에 대응해 원음을 보존하며 발화 구간별로 순차 인식, 모든 구간 성공 후 한 메모로 저장.
- 앱·로컬 백엔드 소스, 자동 검사와 설정·검증 문서. 8단계 개인 입력 의존 수동 진단 하네스·시연 assets·원시 로그는 로컬에 보존하며 이번 게시에서 제외한다. 해당 실행 결과와 한계는 문서로 제공한다.

## 다른 컴퓨터에서 시작하기

1. 새 작업 폴더에 아래처럼 소스를 받는다. 기존 작업 폴더를 덮어쓰지 않는다.

   ```sh
   git clone --branch release/v0.1.0 https://github.com/chowonbhin/Pleos.git Pleos-v0.1.0
   cd Pleos-v0.1.0
   git log -1 --oneline v0.1.0
   ```

2. [SETUP](../SETUP.md)의 JDK 17·Android SDK·Pleos 전용 이미지/AVD·로컬 서명키 준비와 빌드/설치 절차를 따른다. 검증 환경은 macOS ARM64/Pleos API34이며 모든 OS·일반 Android 에뮬레이터 호환을 보장하지 않는다. 이번 게시에서는 APK를 새로 생성하거나 제공하지 않는다. 사용자는 필요할 때 자기 환경에서 빌드한다.
3. AI 기능을 사용할 때만 [백엔드 안내](../../backend/README.md)에 따라 Python 환경과 의존성을 준비하고, 숨김 입력으로 `OPENAI_API_KEY`, 접근 가능한 `OPENAI_LINK_MODEL`, 앱과 공유할 `MEMORY_LINK_SESSION_TOKEN`을 실행 환경에 넣는다. API 키는 백엔드에만 둔다. 앱의 AI 설정에는 API 키가 아닌 **로컬 서버 주소와 세션 토큰**을 입력한다. 모델 접근 권한과 사용 비용은 실행자의 계정에 따른다.
4. 백엔드는 해당 컴퓨터의 `127.0.0.1`에서 실행한다. 서버가 켜져 있는 동안 전용 기기와 같은 포트를 ADB reverse로 연결한다. SETUP에서 실제 `MV_ADB`, `MV_SERIAL`을 확인하고, 예를 들어 서버가 빈 포트8000을 사용한다면 아래처럼 연결한다.

   ```sh
   "$MV_ADB" -s "$MV_SERIAL" reverse --no-rebind tcp:8000 tcp:8000
   ```

   주차 상태의 앱 AI 설정에 `http://127.0.0.1:8000`과 같은 세션 토큰을 저장한다. 다른 포트면 서버·reverse·앱 주소를 함께 맞춘다. 이미 사용 중인 연결을 덮어쓰지 않는다. 종료할 때 이번에 만든 reverse만 제거하고 서버를 종료한다.
5. 로컬 HTTP는 현재 **debug 빌드**에서만 허용한다. Git의 release 브랜치 이름은 Android의 release 빌드 변형을 뜻하지 않는다. 기존 Android `release` 변형은 HTTP를 거절하고 별도 서명도 없으므로 로컬 실행 안내에서는 debug 변형을 사용한다. 앱 내부 versionName은 기존 `0.0.1-bootstrap`을 유지하며 이번 `v0.1.0`은 Git 소스 버전이다.
6. 키·백엔드가 없으면 로컬 녹음/저장·수동 확인 중심으로 사용한다. 실제 AI 처리는 백엔드와 인터넷 연결이 필요하다. 정상 앱 입구와 마이크·주행 안전 절차는 [TESTING](../TESTING.md)을 따른다.

저장소를 받는 것만으로 설치·인증·API 호출은 실행되지 않는다. 다른 컴퓨터에 현재 사용자의 키/세션/DB/원음을 복사하지 않는다.

## 검증 근거

기존 검증을 재사용하도록 한 사용자 지시에 따라 제품 코드와 동결 해시를 대조하고, 이번에는 APK 빌드·전체 시험·기기/실API 호출·독립 clone 검증을 반복하지 않았다.

- STT 수정 기준: JVM 340/340, Lint 오류0(경고36/힌트2), debug/시험/release-unsigned 빌드 성공.
- 실제 녹음 3개 모두 끝 문장까지 인식하고 원음·STT·DB 재열기 보존. 3번의 추가 단어는 사용자가 실제 발화의 말더듬이라고 확인해 오인식 미확인 항목에서 제외했다. 전사 원문은 변경하지 않았다.
- 기존 캡처 기기 회귀6/6. [STT 상세](../verification/stage8-stt-fix.md).
- 이전7단계 JVM323/backend fake190, 신규 기기13/13 및 사용자 수락 근거는 [7단계 검증](../verification/stage7-memory-links.md)과 [후속](../verification/stage7-root-followup.md)에 있다. 이전 통합 기기142/146과 UI 실패4개를 전체 통과로 바꾸지 않는다.
- [8단계 리허설](../verification/stage8-rehearsal.md)은 격리 합성 자료로 저장·검토·수동 연결·공유 경계를 확인한 결과다. 정상 런처부터 시작하는 무주입 전체 시연 성공으로 확대하지 않는다.

## 알려진 제한과 다음 작업

- 여러 후보에서 AI가 REVIEW/연결0으로 보류할 수 있다. 동일 구절에 여러 사진을 연결하는 후처리 정책과 부분 제안 개선은 후속이다. 사용자는 주차 중 수동 확인·연결을 사용할 수 있다. 수정된 전체 전사의 실제 AI 재검증은 이번 게시에서 수행하지 않았다.
- 실제 내비 도착 수신·저장은 [#4](https://github.com/chowonbhin/Pleos/issues/4), 알림센터 일반 진입은 [#1](https://github.com/chowonbhin/Pleos/issues/1), UI 간헐 실패는 [#2](https://github.com/chowonbhin/Pleos/issues/2)에 남아 있다. 목적지 설정/관측을 실제 방문 확정으로 대신하지 않는다.
- 중간 STT 수정본의 timeout1회 원인은 미확정이다. 최종3회에서는 재현되지 않았다. 잡음·약한 발화·매우 짧은 발화까지 완전 전사를 보장하지 않는다.
- 원본 음성·사진·인식 전문·API 키·세션·서명키·사용량 장부·APK·로그는 게시하지 않는다. 이 릴리즈는 공개 서버 운영 또는 설치 파일 배포가 아니다.
- 후속 우선순위는 AI REVIEW/복수 사진 정책과 알려진 이슈 개선이다. P1/P2, 전체 UI 다듬기, 3D 기억 맵과 촬영은 별도 진행 지시 후 착수한다.

## 이번 게시 판단

- Ruling: v0.1.0을 알려진 제한을 명시한 로컬 실행용 소스 릴리즈로 게시한다 — 사용자가 APK/서버 배포를 제외하고 기존 검증을 수락했다 — 이를 무설정 실행이나 전체 시나리오 통과로 오해하지 않도록 준비 조건과 제한을 공개한다.
- Ruling: 검증된 제품 코드를 유지하고 반복 전체검사 대신 소스/동결 해시·문서·최종 Git 범위를 확인한다 — 사용자 최신 지시와 문서만 추가되는 통합 범위 — 제품 차이가 발견되면 기존 근거 재사용을 중단한다.

# STT 발화 누락 수정 설계

사용자 승인: “일단 릴리즈 준비하자. 누락 해결하고 재확인하고”. 기존 8단계에서 root 직접 수정·검증하며 다른 검증 AI를 사용하지 않는 최신 실행 방식을 유지한다.

## 문제와 근거

사용자가 직접 1번 원음에 대본 전체가 있다고 확인했다. 전체 PCM/WAV 해시는 보존되지만 ON_DEVICE 전체 버퍼 인식은 첫 구절만 반환한다. SDK를 직접 관찰해 8초 동안 종료/최종1개 외 후속결과가 없음을 확인했다. 같은 원음을 쉼 구간에서 분리해 뒤 두 구간을 각각 보내면 누락됐던 두 문장도 반환됐다. 상세 전사는 로컬 전용 `.local/stage8-user-audio/diagnostic-{callbacks,segments}-01/`에 있다.

## 접근

- 완료 콜백을 더 기다리기: 실제8초 관측에 후속결과가 없어 채택하지 않는다.
- 클라우드 STT 교체/대본 보정: 원음 전송 범위와 원문 보존 요구가 달라 채택하지 않는다.
- **선택: 보존한 PCM의 조용한 내부 구간에서 발화를 나눠 동일 ON_DEVICE SDK로 순차 인식한다.** 앱의 PcmSpeechInput이 전체 완료 결과 하나를 제공한다. 외부 인터페이스·녹음15초/전체20초 제한·주행 취소·Room schema는 유지한다.

구간 분리는 PCM16LE/16kHz/mono의20ms RMS 프레임으로 조용한 내부400ms 이상 구간을 찾는다. 낮은20% RMS×2.5를100..300으로 제한해 조용한 구간만 보수적으로 선택하고, 양쪽에 누적300ms 이상 신호가 있어야 경계가 된다. 경계는 무음 가운데 샘플에 두고 원본 바이트를 빠짐/중복 없이 분할한다. 원음과 저장 WAV는 수정하지 않는다. 구간별 실제 STT 결과는 순서대로 공백으로 연결하고 단일 구간 텍스트는 그대로 둔다. 임의 문장/날짜/단어를 추가하지 않는다. 모든 환경에서 완벽한 전사를 보장하지 않으며 고잡음/낮은 음량은 별도 한계다.

구간별 SDK는 새로 초기화하며 이전 SDK를 해제한다. 이전 구간의 늦은 콜백이 다음 구간 결과가 되지 않도록 세대를 구분한다. 어떤 구간이 오류/빈 결과/timeout이면 다중 구간의 일부만 Note로 확정하지 않고 전체 원음을 기존 실패 상태로 보존한다. 한 구간의 빈 결과는 기존 NothingHeard 흐름을 유지한다. 상한16구간을 초과하면 명시적 실패로 남긴다.

## 수락

1. 앞/뒤 실제 발화가 모두 최종 텍스트에 나타나고 입력·저장 원음은 동일하다. 실제 3개 녹음은 신규 배치에서 각1회 확인한다.
2. 분할 시 데이터 보존, 단일 구간 원문 보존, 다중 구간 순서, 중간 오류/빈값, 늦은 콜백, 취소·UNKNOWN·deadline 회귀를 검사한다.
3. 전체 JVM 시험·Lint·양APK 빌드 및 영향 있는 기기 저장 검사를 수행한다. API/백엔드 정책은 변경하지 않는다.
4. 릴리즈 후보 APK·사용 방법·실제 결과와 남은 AI 연결/내비 제한을 보고한다. 릴리즈 수락을 과장하지 않고 main 병합·원격 push·태그·Release 게시 전 확인한다.

## 실기기 결과에 따른 수명 관리 보완

첫 구간 순차인식 수정본은 실기기1번에서25초 timeout이1회 있었다. 제품은 같은 상태로 시험 메타데이터만 추가한 관측에서는3구간이 모두 완료돼 전체 문장이 반환됐다. 앞선 timeout 위치·원인은 미확정으로 보존한다. SDK3.3.1의 stop은 비동기 IOnDeviceStt.close 호출을 예약하므로 완료된 구간에 불필요한 stop을 추가하면 후속 요청과 경합할 수 있다. 완료 Final 수신 뒤에는 listener 해제/release만 수행하고, 미완료·오류·취소에는 기존 stop을 유지한다. pure PcmEngineCleanup으로 이 수명 계약을 회귀 검증하며, 이를 앞선 timeout의 확정 원인으로 주장하지 않는다.

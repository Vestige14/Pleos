# 7단계 기억 연결 — 승인된 토의와 설계

2026-11-15 사용자 승인: 아래 토의 내용을 작업자에게 기록하고 병렬 개발을 시작한다. 기준 main `259cb9abb74ebd3659190de52db42be94ab56428`.

## 사용자 결정 (이전 문서보다 우선)

- 자료 종류는 코드로 구분한다. 사진/음성은 MIME·저장 출처, 내비는 SDK 출처를 사용한다. 확장자만 맹신하지 않으며 AI 분류나 거대한 통합 파일 시스템을 만들지 않는다.
- 원본 음성+불변 STT+선택 위치를 보존한다. 위치 없음은 정상이고 AI 실패가 저장 실패가 되지 않는다.
- 이미지 API는 사진 자체만 분석한다. 고정 시각 설명 지시+메타데이터를 제거한 이미지 이외에 사용자 STT, 목적지, 날짜/GPS/파일명, 다른 기억을 모델 입력에 넣지 않는다. 픽셀에 보이는 설명과 짧은 라벨만 반환하며 장소/날짜/경험/감정을 추측하지 않는다.
- 기억 연결 API는 별도 요청이다. STT, 사진의 저장된 시각적 설명, 시간/위치가 알려진 목적지/방문, 다른 STT 기록의 최소 후보를 사용한다. 원본 음성은 전송하지 않는다. 후보가 없으면 API를 호출하지 않고 저장만 유지한다.
- 10/9 바다 사진과 11/1 녹음한 ‘오늘 간 바다 예쁘더라’는 같은 경험으로 연결하지 않는다. 동일 장소/같은 바다 라벨만으로 다른 날짜의 경험을 합치지 않는다. ‘오늘’ 기준은 녹음 시각이며 재시도/서버 현재 날짜가 아니다.
- 명시적 과거 날짜가 있으면 그 날짜의 근거만 후보로 쓴다. 날짜가 모호하거나 사진/과거 내비 시각이 없으면 같은 경험으로 단정하지 않는다. 내비 설정은 도착 증명이 아니다.
- 주차 중 연결 제안 확인·수정·거절·해제·명시적 재분석을 제공하고 사용자 결정은 늦은 AI 결과가 덮어쓰지 않는다. 원문/기존 사진 확정/공유 제외 규칙은 보존한다.
- UI는 기능에 필요한 최소 변경만 한다. 전체 스타일 다듬기/3D 기억 맵은 P2, 최종 촬영/Release는8단계다.
- A API, B 내비, C 앱 저장/검토를 서로 다른 작업공간에서 병렬 구현한다. 공유 계약/공통 조립/Git은 root 한 명이 소유한다.
- **최신 추가 지시: 작업물이 나온 뒤 별도 검증 작업자 V 한 명이 모든 빌드·테스트·코드 검토·기기/통합 검증을 전담한다. 구현자와 root는 검증을 중복 실행하지 않는다.** 이번 단계는 구현자별 TDD 실행/전체suite/개별 reviewer 반복을 이 지시로 대체한다. 구현자는 코드와 검증할 사례를 인계하며 V가 의미 있는 시험을 작성/실행한다. 실패 수정은 원 구현자, 재확인은 V의 영향 범위만. 실행하지 않은 검사는 통과로 기록하지 않는다.

## 선택한 방법과 이유

선택: 코드로 종류/명백한 날짜 충돌을 걸러내고 이미지 단독 분석 → 설명 캐시 → 별도 기억 연결 API를 사용한다. 사진+발화+목적지를 한 번에 모델에 넣는 방식은 사용자 지시와 충돌한다. 기기 내 이미지 모델 도입은 이번에는 하지 않는다. 범용 벡터DB/전체 개인 라이브러리 업로드도 추가하지 않는다.

기존6단계의 인증·구조화응답·중복방지·사용자 revision/lock·UNKNOWN 재호출 금지·비용 hook은 재사용한다. v1 API/보존된 방문 연결은 호환성을 유지한다. 새 기억 관계는 단순 대상 ID/종류/근거/상태로 보관한다. 기존DB를 지우거나 원본을 이동하지 않는다. DB 확장이 필요하면 additive migration만 제안하고 공통 AppDatabase는 root가 적용한다.

## 실제 동작

새 메모 저장은 즉시 완료된다. 가능한 연결은 별도 대기 상태에서 처리한다. 사진 후보는 시간 조건으로 좁힌 다음 필요한 사진만 분석하고 캐시를 사용한다. 앱의 새 연결 흐름과 기존v1 작업이 같은 메모를 중복 유료 분석하지 않도록 조립에서 처리 경로를 한 곳으로 정한다. 오래된v1 결과/사용자 결정은 유지한다.

주차 화면에서 메모별 대기/제안/확정/연결 없음/확인 필요를 구분하고 연결된 사진·기록을 열람한다. 실패해도 원음·STT·공유는 사용 가능하다. 주행/UNKNOWN에서는 검토·수정·사진 업로드 시작·외부 열기·원음 재생이 잠긴다. 백그라운드의 텍스트 결과 저장은 주행 팝업을 만들지 않는다.

## 검증·완료 경계

V 한 명: 작업별 핵심 사례 → 통합본에서 필수 Android/backend/기기 범위 한 차례 → 실패의 영향 범위 재확인. 수정 없는 suite/SDK/마이크/API 반복 금지. 코드 검토도 V가 독립 수행하며 root는 같은 검사를 다시 하지 않는다. root의 Git 범위·비밀정보 게시 점검은 배포 책임이며 기능 시험 반복과 구분한다.

핵심: 사진 요청 맥락 격리, 날짜 반례, 후보 없음0호출, 실제 목적지 지원/누락, 사용자 결정/원문 보존, 재시작/늦은응답, 주행 잠금, 정상 제안→확정→공유 유지. 기존 무음SDK 실패/NoRoot는 별도 상태로 유지하고 반복 통과를 목표로 삼지 않는다. 실제 사용자 마이크는 새로 요구하지 않는다. 실API는 기존 누적 예산 안에서 V 단독 조정으로 필요한 합성 사례만 실행하며 원본 사용자 사진/음성은 시험 업로드하지 않는다.

Stage7 결과와 미검증 한계를 보고하고 중단한다. 새 main merge/push/Release나Stage8 착수는 이번 개발 지시만으로 하지 않는다.

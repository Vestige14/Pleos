# 8단계: 독립 시연 자료와 리허설

## 승인 범위
2026-11-15 사용자가 시연 자료 제작 및 리허설을 지시했다. 촬영은 차후로 미룬다. 앱 UI 재디자인, 릴리즈/태그/제출/원격 push는 이번 범위가 아니다.

## 역할과 자료 격리
- 새 비개발 에이전트 한 명: 사진·공개 목적지·상황 카드 준비. 개발 참여 이력/구현 코드를 전달하지 않는다.
- 기존 개발 에이전트: 이번 자료·기대 결과에 접근하도록 요청하지 않으며 작업을 재개하지 않는다.
- root: 환경·예산·기기·기록 및 사용자 녹음 조율, 정상 앱 리허설. 자료 준비 완료 전 제품/APK를 동결한다.
- 자료와 기대 결과는 `.local/stage8-blind/`에 별도 보존한다. 공유 파일시스템의 물리적 접근 차단을 주장하지 않고 작업 지시·정보 전달을 분리한다.
- 새 담당자는 공개 요구 문서는 읽되 구현 소스·기존 시험 정답을 읽지 않는다. 정상 성공만을 위해 데이터를 바꾸지 않는다.

## 자료
- 내장 imagegen을 우선 사용해 합성 시연 사진을 제작한다. 필요시 재사용 가능한 공개 자료와 출처를 사용한다.
- ui-ux-pro-max/ui-styling은 사진 미리보기·상황 카드 가독성에 적용한다. Android 제품 UI나 웹 의존성은 변경하지 않는다.
- 사용자가 실제 말한 음성과 그 STT를 문장 기준으로 삼는다. 미리 쓴 정답 문장을 읽게 하거나 STT를 맞춰 쓰지 않는다.
- 사진의 시험 날짜/장소 메타데이터는 합성임을 표시하고 사용자의 원본 파일은 변경하지 않는다.
- 사진 분석 입력에는 사진만 제공하며 음성·목적지·기대 정답을 넣지 않는다. 연결 단계에서만 허용된 기록을 사용한다.

## 순서
1. 제품 커밋/APK 동결, 독립 담당자가 4장 안팎의 사진과 공개 목적지·상황 카드 준비 및 manifest 생성.
2. 자료를 사용자에게 제시하고 실제 녹음 가능한 시점을 요청한다. 마이크는 안내·조율 후에만 사용한다.
3. 정상 앱에서 원음/STT 저장 → 사진·내비 근거 수집 → AI 연결 → 주차 검토·수정 → 재진입 보존 → 공유 미리보기/PNG를 리허설한다.
4. 실제 결과를 먼저 기록한 뒤 독립 담당자의 기대 결과와 비교한다. 연결 근거가 없거나 다른 날짜인 사례도 포함한다.
5. 필요한 실패 범위만 진단한다. 전체 suite·동일 성공검사 반복이나 촬영은 하지 않는다.
6. 실행한 결과/남은 이슈/촬영 전 준비사항을 보고하고 중단한다.

## 제한
- API 누적 예산과 키는 기존 로컬 통제만 사용하며 문서에 금액·비밀값을 쓰지 않는다. 내장 이미지 도구 실패 시 유료 CLI로 자동 전환하지 않는다.
- 내비 실제 도착은 이슈 #4의 미검증 범위로 유지한다. 목적지 설정/관측을 도착 성공으로 표시하지 않는다.
- 알려진 UI 간헐 실패 #2를 보존한다. 데이터 손실·안전 위반·핵심 리허설 불능은 구분해 보고한다.

Ruling: 구현을 고정한 독립 자료 제작 → 실제 사용자 발화 → 결과 관측 → 기대값 대조 순서를 채택 — 개발 코드에 맞춘 정답 주입을 피하라는 사용자 의도 — 공유 작업공간이므로 암호학적 맹검이나 접근 통제를 보장하지 않음.

## 사용자 후속 정정: 합성 음성 포함 3회 리허설

사용자가 새 독립 에이전트에 사진 검색·목적지·문장 설정과 가능한 합성 음성 제작까지 위탁하고 리허설 약3회를 요청했다. 이번 합성 리허설에서는 실제 사용자 발화 대기를 제외한다. 기존 실제 음성 검증을 대체하거나 사용자 목소리를 복제하지 않는다. 새 담당자에게 같은 소유범위로 후속을 전달했다(dispatch ctx_4f2741565f94).

- 설치된 한국어 stock TTS(`say`, Yuna 등)와 `afconvert`로 로컬 음성 파일 제작을 우선한다. 마이크/스피커를 자동으로 열지 않고 유료 음성 API·추가 설치 없이 준비한다.
- 관련 기억 있음 / 비슷하지만 다른 날짜 / 관련 근거 없음의 서로 다른 조건으로 각1회 진행한다. 실패를 통과할 때까지 반복하지 않는다.
- 합성 음성은 실제 ON_DEVICE STT 입력 경로로 처리하고 인식된 결과를 사용한다. 정답 문장을 STT 결과로 직접 저장하지 않는다. AudioRecord/사용자 마이크 검증과 구분한다.
- 원본 음성·STT·연결 및 주차 검토·공유까지 진행 가능한 경계를 확인하고, 기존 개인 기록의 외부 전송 없이 격리된 합성 입력만 사용한다. 주입 또는 격리 경계는 결과에 명시한다.
- 상세 기대값은 실제 결과 기록 후 열람한다. 영상 촬영·Release·push는 계속 제외한다.

## 사용자 후속 정정: docs 시나리오 우선

사진·음성·문장·목적지는 원문 문서의 칼국수집→해변→카페 하루 시나리오를 바탕으로 독립 담당자가 준비한다. 첫 회는 기록→연결→주차 확인/수정→카페 제외 공유의 정상 흐름, 둘째는 비슷한 사진의 다른 경험 날짜 구분, 셋째는 관련 자료 없는 발화의 저장만 처리다. 공유에는 원문/좌표 등 비공유 정보를 제외한다. 구체 입력은 개발자에게 미리 전달하지 않는다. 실제 사용자 기억이나 실제 도착을 합성 자료로 증명한 것처럼 표시하지 않는다. 기존 제작물은 보존하며 새 방향에 맞는 부분을 재사용한다.

## 사용자 후속 정정: 리허설 → 가용 릴리즈 → 후속 기능

사용자는 순서를 리허설 결과 정리·필요 수정 → 사용 가능한 첫 릴리즈 준비 → 후속 기능 개발로 정했다. 영상 촬영은 이 순서에서 제외하고 사용자가 차후 요청할 때 가용 릴리즈를 기준으로 진행한다. 영상이 없다는 이유만으로 실행 가능한 버전의 릴리즈 준비를 미루지 않는다. APK·실행 안내·알려진 제한 및 소스 일치는 유지한다. 실제 외부 게시와 후속 기능의 확정 범위는 구체 결과/설계와 사용자 지시에 맞춰 처리한다.

자료 담당자의 기존 준비는 계속한다. 현재 root와 사용자는 기다리는 동안 후속 기능을 논의하며, 이 대화만으로 P1/P2 구현을 시작하지 않는다. 기존 원문에서 P1로 명시한 것은 F11 출처 배지 확장·F12 사진 이동이고 F13 문장 다듬기·F14 링크 공유 등의 정확한 버전 배정은 후속 논의로 정한다. P2의3D 기억 맵과 전체UI다듬기 결정은 유지한다. 원음 보관/기억 연결은 이미6·7단계에 구현됐으므로 다시 미구현후속으로 세지 않는다.

## 2026-11-15 사용자 결정: 내비 데모 대안과 개선 판단

- 실제 내비 도착 이벤트를 에뮬레이터에서 재현할 방법이 확보되지 않으면, **데모용 목적지 기록을 별도로 생성·준비하여 차후 영상 시나리오를 진행**한다. 칼국수집→해변→카페 자료와 연결하되 합성/사전 준비 기록임을 구분하고 기존 사용자 기록을 덮어쓰지 않는다.
- 목적지 기록은 목적지 설정/관측의 근거이며, 실제 SDK 도착 수신이나 방문 확정으로 위장하지 않는다. 실제 도착 수신·저장 공백과 이슈 #4는 유지한다. 데모 기록 생성 방식의 상세 구현은 아직 없으며 이번에는 방향만 기록한다.
- 촬영은 사용자 후속 요청 때 진행한다. 이 결정으로 지금 촬영·Release·push를 시작하지 않는다.
- API 개선 판단: 기억 연결 모델/추론 강도 상향은 비교 후보지만 REVIEW 원인은 미확정이다. 현 프롬프트의 보수적 모호성 정책 및 응답 검증도 REVIEW를 만들 수 있으므로 동일 입력의 모델 응답과 후처리를 구분해야 한다. 사진 단독 설명5건은 이미 성공해 우선 교체 근거가 없다.
- 날짜 문제는 Pleos ON_DEVICE STT가 11월을12월로 인식한 것과 로컬 날짜 규칙이 이를 전년도 날짜로 해석한 것이 결합했다. 기억 연결 API 모델만 바꿔 해결되지 않는다. 원음·STT 원문을 보존하면서 별도 경험 날짜 확인/보정 흐름을 우선 검토한다. 클라우드 STT는 음성 외부 전송 범위가 달라지므로 이번 API 질문을 전송 승인으로 해석하지 않는다.
- 다음 비교를 실행한다면 기존 입력을 고정해 현 설정·추론 강도 상향·상위 모델을 소수 대표 사례에서 비교한다. 다른 날짜 잘못 연결/근거없음까지 함께 보며 성공할 때까지 반복하거나 전체 리허설을 매번 돌리지 않는다. 이번에는 모델 변경·유료 호출·제품 코드 변경을 하지 않았다.

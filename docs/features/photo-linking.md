# 사진 연결 · 4단계 실행과 수락

## 구현된 동작

- MediaStore 사진을 읽고 EXIF 촬영 시각·GPS를 검증한다. 명시 offset이 없으면 Asia/Seoul을 사용한다. 방문 체류 시간의 양끝과 300m 이내를 후보로 연결하며 시각/GPS가 없으면 미연결로 남긴다.
- 개별 URI 읽기 오류와 전체 스캔 실패/취소를 구분한다. 목록에 없다는 이유만으로 사진을 삭제하거나 접근 불가로 확정하지 않고 기존 URI도 실제 읽기를 확인한다.
- 사용자 CONFIRMED/REJECTED 결정과 방문 연결은 재스캔·접근 권한 변화·동시 결정에서도 보존한다. Room v1→v2는 accessible 열을 추가하는 비파괴 migration이다.
- 주차·foreground·drive generation이 유효할 때만 사진 작업/썸네일을 허용한다. ON_STOP·UNKNOWN 등 무효화 시 CancellationSignal로 읽기를 취소하고 늦은 결과를 표시하지 않는다. 명시적 재스캔은 같은 URI의 썸네일 실패도 재시도한다.

## 실행과 실제 확인

[SETUP](../SETUP.md)으로 자신의 전용 AVD·JDK·SDK·서명 설정을 확인하고 빌드/설치한다. 제품 APK는 `app/build/outputs/apk/debug/app-debug.apk`다. 기존 설치 업데이트는 같은 서명을 확인한 뒤 `install -r`로 수행하며 데이터를 삭제하지 않는다.

1. 공식 콘솔에서 P·0을 확인한다. 최초 차량 속도 권한이 없으면 UNKNOWN 잠금이 정상이다. 승인된 전용 기기의 정상 시스템 앱 권한에서 차량 속도를 허용한다. 현재 Pleos 이미지에서는 ‘위치’ 그룹이다.
2. 일반 앱 목록의 **기억 저장소**를 열고 ‘사진 권한 · 다시 선택’을 누른다. 전체 사진 허용 후 후보 썸네일을 확인한다. 음성 권한 버튼이나 마이크는 사진 시험에 필요하지 않다.
3. 사진을 확정하거나 연결 해제한다. ‘사진 다시 읽기’, 사진 권한 철회/재부여, 앱 프로세스 재실행 후 결정이 유지되는지 확인한다.
4. 공식 콘솔 D와 차량 상태 UNKNOWN에서 사진·편집 UI가 숨겨지는지 확인하고 P·0으로 복구한다.

macOS에서 개인 사진 없이 시연 fixture를 만들 수 있다. 기존 파일을 덮어쓰지 않는 새 출력 폴더를 사용한다.

```sh
swift scripts/generate_photo_fixtures.swift .local/photo-fixtures-new
```

이 스크립트는 JPEG 7장의 EXIF를 생성 후 다시 읽어 검증한다. 대상 사용자 MediaStore에 등록하고 실제 파일 hash를 대조한다. 기존 사용자 사진을 덮어쓰거나 일괄 삭제하지 않는다. 2026-11-08 기준 p1 식당12:25, p2/p3/p4 해변13:45/14:10/14:30, p5 카페15:20, p6 해변14:12 합성 영수증, p7 시각/GPS 없음이다. 초기 후보는 식당1·해변4·카페1, p7은 미연결이다. 다른 메타데이터 없는 합성 PNG가 추가되면 미연결 수가 늘 수 있다.

실제 전용 Pleos AVD에서 후보1/4/1, 식당p1 확정·영수증p6 해제→해변3장, 재스캔/권한 철회재부여/프로세스 재실행 후 보존, D/UNKNOWN 숨김을 확인했다. 사용자가 차량 속도·합성 사진 권한 시험을 명시적으로 승인했다. 마이크는 미허용이며 다른 AVD/기존 음성 데이터는 변경하지 않았다.

## 알려진 한계와 후속 작업

- 전체 사진 허용·거부·철회·재부여를 이번 4단계 수락 범위로 정했다. 현재 Pleos OS는 선택 사진 또는 촬영 GPS만의 독립 토글을 제공하지 않아 해당 실제 조합은 미검증이다. 기존 관련 순수 로직 검사는 실제 OS 검증을 대체하지 않는다.
- [이슈 #2](https://github.com/chowonbhin/Pleos/issues/2): 기존 Compose UI 테스트의 입력 노드 부재·NoRoot·idle timeout. 임시 진단을 포함한 성공 회차와 제거 후 실패 회차를 모두 기록했다. 원인 미확정이며 사용자 승인으로 이번 게시의 차단 조건에서 제외했다. 테스트와 안전 gate는 유지한다.
- 이 브랜치에 공유 선택/미리보기/저장·Android 공유 시트, Android AI Worker, 실제 OpenAI 호출은 없다. 다음은 5단계 공유 화면·흐름이며, 최신 후속 실행 지시에 따라 이어 간다.
- 이번 체크포인트는 첫 릴리즈가 아니다. 버전/태그/Release를 생성하지 않는다.

## 검증 결과

사진 전용 소스의 빌드 성공·JVM 178개 통과·Lint 오류 0을 확인했다. 기기 전체65메서드는 61성공·4실패 메서드/5실패 이벤트이며 사진 관련 새 검사22개는 통과했다. 실패는 기존 MemoryVaultScreenTest의 NoRoot/ActivityScenario lifecycle 경계로 이슈 #2에 남긴다. 상세 결과와 APK hash는 [인수인계](../HANDOFF.md)에 기록했다. 이전 병렬 조사78개에는 공유13개가 포함돼 있어 이 브랜치의 전체65개와 구분한다. task 사진37파일의 독립 fix1 검토는 I1 썸네일 안전·M1 재시도 ADDRESSED 및 Approved였으며, optional UseKtx 권고는 비차단 후속 항목으로 남았다.

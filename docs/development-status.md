# 개발 상태와 재개 안내

기준: 2026-11-14. 사용자가 3단계의 남은 작업을 재개하도록 요청해, 검토된 3A 저장 코어에 3B 안전 정책·음성 세션 코어를 추가했다. 원래 설계의 실제 차량·음성·화면 연동 조건은 남아 있어 **3단계 전체는 미완료**다. 주차 화면에 음성 입력을 추가하거나 OS 주행 제한을 해제하는 대안은 채택하지 않았다.

## 완료 범위와 남은 범위

### 단계별 진행 방식 — 2026-11-14 사용자 정정

앞으로는 각 단계의 구현·필수 검증·검토를 마친 뒤 **결과를 보고하고 작업을 중단**한다. 실행 가능한 결과물과 확인 방법, 검증 결과, 남은 문제, 다음 단계 내용을 전달하고 사용자의 명시적인 재개·진행 지시를 기다린다. 기준은 1~8단계 로드맵이며 별도로 합의한 세부 단계에도 적용한다. 기존의 ‘계획 승인 후 단계별 중단 없이 연속 실행’ 규칙보다 이 결정이 우선한다. push 승인은 다음 단계 진행 승인을 대신하지 않는다. 이번 재개는 3단계에 한정하며 4단계를 시작하지 않는다.

| 범위 | 상태 |
| --- | --- |
| 1단계 초기 환경·빈 앱 | 완료. 독립 clone 빌드·실행 확인 |
| 2단계 플랫폼 실험 | 완료. 실제 오프라인 STT 결과를 사용자가 확인했고 차량 상태·OS 제한을 기록 |
| 3A 저장 코어 | Room 스키마·시드·직접 메모·음성 원문 원자 저장·AI 대기 데이터·조회 및 테스트 구현 |
| 3B 안전 정책·음성 세션 코어 | 상태별 화면/편집/공유 정책과 제한 시간·취소·최종 원문 1회 저장 조정 구현. 실제 SDK·UI 미연결 |
| 3단계 전체 | **미완료**. 실제 화면·STT 저장 경로·앱 프로세스 재시작·차량 안전 통합은 아직 없음 |
| 4단계 이후 | 미착수 |

현재 `MainActivity`는 초기 화면이다. 저장 코어를 구현했다는 사실이 사용 가능한 메모 화면이나 전체 데모 완성을 뜻하지 않는다. 이 단계에는 네트워크 API·Worker·실제 AI 호출도 없다. 3단계는 개발 체크포인트이며, 아래 첫 릴리즈 기준을 충족하기 전에는 릴리즈를 생성하지 않는다.

3A의 Room 저장은 Note·정책·AI job·후보 snapshot을 같은 트랜잭션으로 처리한다. 같은 음성 세션은 하나의 메모만 만들고, 원문은 수정하지 않는다. 방문이 없어도 저장하며 후보는 원래 날짜와 녹음 시각을 기준으로 고정한다. AI 제안과 사용자 확정은 조회 결과에서도 구분한다. 사진은 후속 데이터 계약만 있으며 스캔·사진 연결 기능은 아직 없다.

메인이 3B 추가 소스에서 새로 실행한 검증은 JVM **48/48**, 새 전용 AVD의 실제 Room **27/27**, Lint **오류 0·경고 13**이다. 앱과 테스트 APK 빌드도 성공했다. Room 복원 테스트는 별도 UUID 이름의 파일 DB를 닫았다 다시 여는 검사다. **앱을 종료·재실행하는 전체 제품 시연을 대신하지 않는다.** 경고는 기존 11건과 고정한 coroutines core/test 1.7.3의 업데이트 권고 2건이다. 기존 런타임 해석 버전과 테스트 버전을 맞췄으며, SDK XML 도구 버전 경고도 별도 환경 점검 대상이다.

3B 정책은 UNKNOWN에서 Locked, 주행 중 Driving으로 제한하고, 편집·공유는 PARKED에서만 허용한다. 새 음성 시작은 원안대로 DRIVING에서만 허용한다. 이는 신뢰된 차량 상태를 소비하는 순수 정책이며, 차량 API 값으로 신뢰성을 판정하는 어댑터는 아니다.

음성 세션은 15초에 캡처를 멈추고 시작 후 20초까지 최종 결과를 기다린다. 유효한 최종 결과를 받으면 원래 세션 ID·시각·원문 그대로 한 번 저장하며 방문이 없어도 저장 경로를 호출한다. 20초는 인식 결과의 도착 제한이므로 이미 수락한 저장은 더 늦게 끝날 수 있다. UNKNOWN·사용자 취소·호출자 취소를 처리하고, 일반 자원 정리 실패는 저장 결과와 구분한다. 취소가 저장 완료와 겹치면 실제로 커밋된 메모를 삭제하지 않는다. 실제 Pleos SDK 해제·Android lifecycle·화면 동작은 후속 연동 검증 대상이다.

`allowBackup=false`와 두 형식의 백업 제외 규칙을 적용했고 APK에 포함된 규칙을 확인했다. 로컬 테스트 DB, 키·로컬 설정, APK·로그·화면 자료는 Git에 포함하지 않는다. 저장소의 Room schema JSON은 실제 사용자 DB가 아닌 구조 정의이며, 시드 방문과 테스트 문장은 합성 시연 데이터다.

## 첫 릴리즈 범위 — 2026-11-14 사용자 결정

사용자는 **F1~F10 + OpenAI 방문 연결·사용자 확인 + 통합 검증**까지를 첫 번째 릴리즈로 정했다. 첫 릴리즈 버전은 `v0.1.0`, 릴리즈 브랜치는 `release-v0.1.0`으로 계획한다. 이는 완료 목표의 확정이며 현재 구현 완료를 뜻하지 않는다.

- F1~F2: 주행·UNKNOWN 안전 잠금과 실제 오프라인 음성 메모 경로.
- F3~F7: 시드 방문 로드, 하루 초안, 사진 후보 연결·확정·해제, 직접 메모 추가·수정.
- F8~F10: 공유 항목 선택, 원본과 분리된 공유본·미리보기, PNG 저장·Android 공유 시트.
- v3 추가 범위: 음성 원문 우선 저장, 재접속 후 실제 OpenAI 방문 연결 제안, 복수 방문·모호한 발화 처리, 주차 중 사용자 확정·수정·거절, 재시도·중복·늦은 응답으로부터 사용자 결정 보호.
- 완료 검증과 산출물: 새 clone에서 제외 파일 복사 없이 빌드·실행, 실제 Pleos AVD 통합 검증, 앱 재시작 복원, 권한 변화·안전 상태 전환·통신 실패 처리, 공유 개인정보 제외 및 비밀정보 검사, 독립 최종 검토, 실행 가능한 APK·공유 PNG·시연 영상·README와 검증 기록. 실제 API 대표 발화 검증 등 기존 세부 수락 기준도 유지한다.

출처·후보·확정 상태의 최소 구분 표기는 포함한다. F11 전체 배지 확장, F12 사진 이동, F13 문장 다듬기, F14 링크 공유, F15 3D 기억 맵은 첫 릴리즈 범위 밖이다. 실제 방문 감지, 휴대폰 연동, 계정·기기 동기화, 기억 간 자동 연결·회상, 원본 음성 보관·동승자 대화 수집도 포함하지 않는다. 후속 릴리즈의 범위와 버전은 아직 정하지 않았다.

기존 v4 로드맵의 1~8단계 구현 순서는 유지하되, 3·5·7단계는 중간 개발 체크포인트로 관리한다. **3단계 v0.1.0 → 5단계 v0.2.0 → 7단계 v0.3.0 → 8단계 v0.4.0이라는 옛 버전 배정은 이 결정으로 대체한다.** 8단계까지 첫 릴리즈의 전체 수락 기준을 충족한 검증 커밋에서 `release-v0.1.0`과 `v0.1.0` 태그를 만든다. 원본 계획 문서는 이력으로 보존한다.

차량 안전 연동과 필수 음성 경로가 미해결이면 첫 릴리즈 완료로 표시하지 않는다. 기능별 실행 결과·검증·독립 검토와 push 확인 절차는 유지한다. 원격 push·GitHub Release 게시·배포·제출은 별도 승인 범위이며, 이번 결정으로 실행하지 않는다.

## 안전 연동의 미해결 사항

상세 관측과 재현 절차는 [플랫폼 실측 기록](environment/mv-02-platform-spikes.md)에 있다.

- 현재 Pleos 이미지에서 주행용 Activity도 OS 차단 화면에 가려진다. 설치 출처 거부 기록이 있지만, 지원되는 개발 설치 절차는 추가 확인이 필요하다.
- 콘솔 원천 연결이 끊겨도 표준 차량 API가 정상값을 계속 반환했다. 원천 단절을 신뢰성 있게 UNKNOWN으로 바꾸는 계약은 해결되지 않았다.
- 오프라인 STT 자체의 성공을 실제 주행 중 음성 저장 기능 완료로 확대하지 않는다.
- 가상 기기의 네트워크 설정 복원과 실제 인터넷 재접속 여부는 구분해 확인해야 한다.

원안의 UNKNOWN 잠금·주행 중 편집/공유 제한·필수 음성 기능을 삭제하거나 완화하지 않는다. 다음 UI·플랫폼 통합 전에 위 조건을 해결하거나 사용자에게 구체적인 범위 변경 승인을 받아야 한다.

## 코어 검증 재현

[README](../README.md)의 JDK 17·SDK 및 로컬 디렉터리 준비 후 실행한다. 프로젝트에서 제외된 파일을 복사할 필요는 없다.

```sh
./gradlew --no-daemon --console=plain testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Room 검증에는 전용 새 AVD와 전용 ADB 서버를 사용한다. `MV_SERIAL`과 `MV_USER_ID`를 그 기기의 실제 값으로 설정하고, 앱과 테스트 APK를 **기존 앱이 없는 새 기기**에 설치한 뒤 아래 명령을 실행한다. 다른 프로젝트 기기에 덮어쓰거나 서명 충돌을 해결하려 기존 데이터를 삭제하지 않는다.

```sh
: "${MV_SERIAL:?전용 새 AVD serial을 설정하세요}"
: "${MV_USER_ID:?그 AVD의 실제 사용자 번호를 설정하세요}"
: "${ADB_SERVER_SOCKET:?전용 ADB 서버를 설정하세요}"
"$ANDROID_HOME/platform-tools/adb" -s "$MV_SERIAL" shell am instrument \
  --user "$MV_USER_ID" -w -r \
  -e class app.memoryvault.data.VisitDaoTest,app.memoryvault.data.MemoryRepositoryTest,app.memoryvault.data.AiLinkQueueTest,app.memoryvault.data.MemoryPersistenceTest,app.memoryvault.data.NotePresentationTest \
  app.memoryvault.test/androidx.test.runner.AndroidJUnitRunner
```

`am` 명령의 exit code만 확인하지 않고 `OK (27 tests)`와 개별 실패 유무를 확인한다. 테스트는 in-memory DB 또는 자신이 만든 `mv03a-test-<UUID>.db`만 사용·정리한다. 마이크·차량 정책·네트워크 설정을 바꾸는 테스트가 아니다.

## Git 운영 기준

2026-11-14 사용자 정정에 따라 이전 계획의 develop 중심 운영 대신 아래 흐름을 따른다.

1. 검증된 최신 `main`에서 작업 브랜치를 만든다.
2. 해당 기능의 구현·검증·독립 검토가 끝나면 `main`에 병합한다.
3. 릴리즈 완료 기준을 충족한 경우에만 그 커밋에서 릴리즈 브랜치와 버전 태그를 만든다.
4. 원격 push 전에는 feature/main/릴리즈의 정확한 파일·이력·커밋 범위를 보여 주고 사용자 확인을 받는다.

현재 완료 기준선은 2단계 `0c5383d`다. 미완료 3단계의 진행분은 `feature/03-offline-memory`에 보존하고, `main`에 완료된 기능처럼 병합하거나 릴리즈로 표시하지 않는다. 기존 develop과 작업 브랜치는 임의로 삭제하지 않는다. 3단계 통합은 위의 미해결 플랫폼 조건이 필요하며, 4단계는 별도 진행 지시 없이 시작하지 않는다.

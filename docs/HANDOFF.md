## 2026-11-14 최신 저장 계약 — 캡처 위치는 선택 정보

사용자: “6단계의 녹음 당시 위치는 못얻을 상황이면 그냥 위치 정보 없음으로 저장해도 돼”. 녹음 당시 유효한 위치를 얻지 못하면 위치 정보 없음으로 저장하며 원본 음성·STT 텍스트 저장을 위치 확보 때문에 실패시키거나 계속 대기시키지 않는다. 권한 거부·제공자 미지원/오류·시간 내 응답 없음·유효성/신선도 기준 미충족은 위치 없음으로 처리할 수 있다. 오래된 위치·시드 좌표·내비 목적지를 현재 캡처 위치로 대신 넣지 않는다. 실제 누락은 null/명시적 없음으로 구분하며 (0,0)을 누락 표시로 쓰지 않는다.

이 결정은 위치 취득 가능 경로의 구현·검증을 생략한다는 뜻이 아니다. 유효한 위치가 제공되면 출처·시각 계약에 따라 저장하고, 제공되지 않는 경로에서도 음성/STT 기록이 보존되는지 검증한다. 권한을 우회하거나 주행 중 권한창을 띄우지 않는다. 기존 차량 속도/주행 상태의 안전 잠금은 캡처 위치의 선택 여부와 별개이며 그대로 유지한다. 이 저장 계약은 확정됐지만 원본 음성·위치 저장 구현 완료를 뜻하지 않는다.

Ruling: 캡처 위치 부재를 음성/STT 저장의 차단 조건에서 제외한다 — 사용자가 위치 없음 저장을 명시적으로 허용했다 — 후속 연결의 단서가 줄 수 있으므로 누락을 실제 좌표로 가장하지 않고 7단계에서도 위치 없이 처리한다.

## 2026-11-14 최신 단계 경계 — 6단계 기반 우선 · 기억 연결 확장은 7단계

사용자가 “그 ai 연결은 7단계에서 해도 되지 않나?”에 이어 “6번은 그렇게 해. 7단계로 미룰것만 미루고 6단계에서 해야할 거는 하고”라고 승인했다. 아래 과거 절보다 이 경계를 우선한다.

- **6단계:** 기존 AI 통신·인증·대기열·재시도·응답 저장과 사용자 확정 보호를 안정화한다. 독립 검토 I1/M1 수정, 실제 API 합성 시나리오·사용량 수락을 유지한다. 원본 음성 + STT 텍스트 + 캡처 위치를 보존하는 수집·저장 기반도 누락하지 않는다. 플랫폼 조사 결과를 바탕으로 실제 입력 가능성·실패 처리·보존 계약을 정리해 검증하며, 조사만으로 구현 완료를 선언하지 않는다.
- **7단계:** 사진 내용 해석 및 저장된 사진·내비 목적지·다른 음성 기억 간의 의미 기반 연결을 확장하고 사용자의 확인·수정·해제를 구현한다. 근거가 없으면 연결하지 않고 원본 기록만 유지한다. 기존 시간/GPS 사진 후보와 현재 텍스트→방문 연결은 보존하며, 새 다중 기억 해석을 6단계 완료 조건으로 추가하지 않는다.
- 내비 최근 목적지 조회는 공식 계약이 있지만 방문 시각 필드가 없으므로 날짜 있는 방문 이력으로 가장하지 않는다. 6단계의 캡처 위치 저장과 7단계의 내비 근거 활용을 구분한다.
- 원본 음성은 현재 미구현이다. 기존 STT request의 원음 반환은 확인되지 않았고, 단일 AudioRecord의 PCM을 로컬 파일과 ON_DEVICE sendAudio에 함께 전달하는 경로가 검증 후보다. 실제 기기 성공·마이크 시험은 아직 없으며 실제 발화 시점은 사용자와 조율한다. 사진/원음 외부 업로드, 상시 위치 수집, 자동 모델 대체는 이 결정으로 추가하지 않는다.
- 5단계 최종 검증은 계속한다. 7단계 착수·전체 UI 다듬기·원격 push·Release는 현재 진행 범위에 포함하지 않는다. UI 다듬기는 기존 결정대로 P2/3D 기억 맵 때 진행한다.

Ruling: 사진 내용 기반 다중 기억 연결은 7단계로 이관하고 6단계 통신·검증 및 수집/저장 기반은 유지한다 — 최신 사용자 승인과 기능 의존성에 맞춰 6단계 범위의 불필요한 확대를 막는다 — 저장/연결 계약을 잘못 나누면 7단계 데이터 구조·API 재작업이 생길 수 있어 연결 확장을 고려한 식별자·출처·시각 계약은 구현 전에 정리한다.

## 2026-11-14 실행 재개 — 5단계 검증과 6단계 변경 준비 병행

사용자가 “6단계도 진행해 바로”라고 명시하여 직전 6단계 보류를 해제했다. 5단계 독립 재검토/수락은 계속하고, 6단계는 기존 구현의 독립 검토 결함 수정과 확정된 새 기억 처리 요구의 플랫폼 조사·설계/계획 정리를 재개한다. 원본 음성+STT+위치 보존 및 기존 사진/내비 목적지/다른 음성 기억과의 근거 기반 연결을 목표로 한다. 연결할 기록이 없으면 저장만 유지한다.

## 2026-11-14 최신 요구 확정 — 원본 음성 보존과 기억 간 연결

사용자는 “해변에서의 노을이 좋았어”라는 기록을 예로 다음 동작을 명시했다. 원본 음성 + STT 텍스트 + 위치 데이터를 저장하고, AI는 이미 저장된 기억에서 관련 노을 사진·내비게이션 목적지 기록·다른 음성 기록 등이 있으면 연결한다. 관련 근거가 없으면 연결을 억지로 만들지 않고 기록만 저장한다. TTS가 아니라 **원본 음성 + STT 텍스트 저장**임을 추가 답변으로 확정했다. 이는 방문 추천이나 대화형 질문 생성에 대한 요구가 아니다.

이 요구는 기존 v3의 같은 날짜 방문 후보에 메모를 묶는 범위와 원본 음성 미보관 정책을 확장·정정한다. 현재 제품은 STT 텍스트만 저장하며 원본 음성 보존·사진 내용 기반 기억 연결·내비 목적지 이력 수집·기억 간 연결을 구현 완료했다고 볼 수 없다. 기존 구현과 원문 자료는 보존한다.

현재 실행 순서는 **5단계 확인 우선, 6단계 실행 보류**를 유지한다. 6단계 재개 전 원본 음성 수집/저장, 위치·내비 기록 확보, 기억 및 연결 데이터 구조, 사진/음성 해석과 전송 범위, 사용자 확인 방식 및 검증 계획을 새 요구에 맞춰 정리한다. 로컬 저장 요구를 모든 원본의 자동 외부 업로드 승인으로 해석하지 않는다. 실제 SDK/API의 데이터 제공 가능성은 확인 전 가정하지 않는다. 이번 요구 확정만으로 마이크 시험·6단계 구현 재개·7/8 착수·push를 실행하지 않는다.

## 다음 담당자의 첫 작업

**3단계를 완료하고 중단한 상태입니다.** 사용자가 내비 유지 조건의 분할 화면을 허용했고 실제 제품 경로를 확인했습니다. 알림센터 자체를 고쳤다고 주장하지 않습니다. 4단계는 별도 진행 지시 전까지 시작하지 않습니다.

1. 먼저 사용자에게 승인된 다음 작업을 확인합니다. 4단계 진행 지시를 받으면 사진 스캔·시간/위치 후보·연결 확정/해제·권한 처리부터 시작합니다. 환경 재현 요청이라면 [TESTING](TESTING.md)으로 source/APK/serial/user를 기록하고 이미 유효한 검사와 변경 영향 범위를 구분합니다.
2. TESTING 6절의 일반 앱 목록→기억 저장소 · 녹음→오른쪽 창 막대 드래그를 재현합니다. D에서 직접 버튼·내비 유지·녹음 상태와 P 설정 복귀를 확인합니다.
3. 실제 발화는 사용자 준비 뒤 수행합니다. 이번 APK의 DEX 감사·오프라인 상태·저장 전후 차이·재실행 보존을 기록합니다. 사용자가 이미 검수한 동일 산출물을 불필요하게 반복 시험하지 않습니다.
4. 초기 편집기 자동 검사의 일시적 실패가 재발하면 첫 클릭 직후 semantics·host lifecycle·dismiss 여부를 좁게 관측합니다. 기존 안전 gate를 완화해 통과시키지 않습니다.
5. 3단계 결과 보고 뒤에는 **중단**합니다. 새 push 승인과 4단계 진행 승인을 구분하며, 4단계는 사용자의 명시적인 지시 후 시작합니다.

상단 아래로 끌기·시각 영역 클릭·Android Meta+N 키 조합에서는 열기 동작을 관측하지 못했습니다. StatusBar disable 플래그 0 및 초기 설정 완료도 확인했습니다. 공식 배포 XML과 릴리스 노트는 v2.1.0을 제시하며, 더 새 수정 이미지는 확인되지 않았습니다. LOW 중요도 하나를 원인으로 단정하거나 같은 중요도 실험·재설치를 무작정 반복할 근거는 없습니다. 공식 문서의 SP0 종 아이콘은 OS 마이크 privacy indicator와 다릅니다. 이는 모든 가능한 진입 경로의 부재를 입증한 결과는 아닙니다.

알림센터 자체는 [이슈 #1](https://github.com/chowonbhin/Pleos/issues/1)로 남습니다. Gleo 재검증에서는 실제 명령 수신 뒤 microphone FGS의 background/while-in-use 시작 거부를 관측했고 실제 녹음으로 이어지지 않았습니다. 전역 핸들 키의 CAR_MONITOR_INPUT은 signature/privileged라 일반 권한 부여가 거부됐습니다. 작은 dialog는 내비를 가렸고 인접 실행 flag는 기대한 분할을 만들지 못해 제품에서 제외했습니다. 해당 결과를 모든 OEM 환경의 불가능으로 확대하지 않습니다.

공식 문의 메일은 사용자가 **발송하지 않고 내용만 보관**하도록 결정했습니다. 새 발송·특권 우회·주행 제한 변경은 실행하지 않습니다. Gleo·전역 버튼은 후속 과제이며 이번 정상 버튼 경로를 대체하지 않습니다.

## 유지할 제품·안전 계약

- **버튼 시작·내비 유지:** 실제 SDK Started 이후에만 `기억 저장소 · 메모 녹음 중`을 표시합니다. 준비·처리·종료는 구분하며 주행 중 원문은 노출하지 않습니다. Gleo 시작은 후속 과제입니다.
- **로컬 원문 우선:** ON_DEVICE 한국어 최종 유효 원문만 한 번 저장합니다. 부분 인식·음성 파일·원문 로그는 저장하지 않습니다. 방문 미지정을 허용하고 최근 방문에 강제 확정하지 않습니다. 원문·정책·job·후보 snapshot을 같은 트랜잭션으로 보존합니다.
- **새 조작의 안전 gate:** 신뢰된 DRIVING에서만 새 녹음, PARKED에서만 편집·권한 준비를 허용합니다. UNKNOWN은 잠금·녹음 취소입니다. 최초 차량 속도 권한이 없으면 UNKNOWN을 유지하고, 시험자가 공식 콘솔 P·0을 확인한 뒤 외부 시스템 설정에서 최초 권한을 준비합니다.
- **세션 수명:** 캡처 최대 15초, 수락 후 최종 결과 도착 최대 20초, 콜드 차량/DB 준비 최대 5초 동안 마이크 미사용. 인식 결과를 수락한 DB 저장의 완료 시각과는 다릅니다. 내비로 Activity가 전환돼도 서비스가 세션을 관리합니다. 사용자 취소·실제 UNKNOWN·서비스 종료 등은 취소합니다.
- **순간 실패 보존:** 현재 안전 상태를 원본에서 읽고 `invalidationGeneration`을 비교합니다. 짧은 UNKNOWN→P/D 복구를 수집 병합이 감추더라도 세션·편집기가 무효화를 놓치지 않습니다.
- **제한된 TRANSITION:** 동일 연결에서 이미 신뢰한 유효 P/D 전달 순서 차이에만 최대 500ms. 새 녹음·편집·공유는 차단하고 수락된 녹음만 기존 제한 내 유지합니다. 반복 callback으로 연장하지 않습니다. 시작·오류·누락·단절·잘못된 값은 즉시 UNKNOWN입니다.
- **저장 결과:** Room 성공 뒤에만 저장 완료를 안내합니다. 취소와 커밋이 겹친 이미 저장된 메모는 삭제하지 않습니다. 음성 원문은 수정 불가이고 TYPED만 수정합니다.
- **초안:** 출발·상태 무효화·ON_STOP에서 편집기와 IME를 닫고 미전송 내용을 숨깁니다. 주차 후 수동으로 이어 쓰며, 다른 대상으로 바꾸기 전에 기존 초안 폐기를 확인합니다. 미전송 초안의 강제 종료 후 영구 복원을 보장하지 않습니다.
- **플랫폼 경계:** 실제 Car API 준비·실패로 판정합니다. 콘솔/browser DDS 단절과 Car/VHAL 단절은 같은 사건이 아니며, 플랫폼이 정상값으로 제공하는 상류 오류를 모두 감지한다고 주장하지 않습니다.
- **로그·백업:** debug/release 모두 R8을 사용하고 제품 debug도 non-debuggable입니다. `run-as`나 debugger를 전제로 시험하지 않습니다. 원문 SDK 로그 제거와 callback 보존을 DEX로 확인하고 백업·기기 전송에서 DB를 제외합니다.

## 브랜치·게시와 매 push 전 갱신

`main`은 검증된 최신 구현·문서, `feature/<기능명>`은 기능 작업, `bugfix/<문제명>`은 수정, `release/<버전>`은 완료 기준을 충족한 릴리즈입니다. 첫 릴리즈는 `release/v0.1.0`과 같은 커밋의 `v0.1.0` 태그로 통일합니다. 이전 `release-v0.1.0` 이름과 develop 필수 통합은 대체됐고 기존 브랜치를 임의로 삭제하지 않습니다.

사용자는 2026-11-14 “3단계 미완상태로 인수인계 넘기고 그냥 push 해”라고 명시해, 현재 구현과 사이드 문서를 **3단계 미완료 체크포인트로 main에 병합하고 origin/main에 게시**하도록 승인했습니다. 이전 자동 승인 검토의 ‘3단계 완료 후 병합’ 조건 충돌은 이 최신 지시로 해소됐습니다. 이번 게시에 한한 명시적 예외이며 3단계 완료·릴리즈·4단계 착수 승인은 아닙니다. 구현·문서와 원본 자료만 반영하고 APK·개인 설정·키·원문 로그는 게시하지 않습니다.

모든 push 전에 아래 내용을 최신 상태로 고칩니다.

- 이번에 개발·변경한 기능과 관련 파일·소스 커밋.
- 실제 확인한 동작과 구현만 됐거나 미검증인 범위.
- 실행·테스트 명령, 사용한 소스·APK·기기, 결과와 실패 이력.
- 남은 문제·결정·판단 근거와 다음 기능의 첫 작업·완료 기준.
- 단계 중단·UI 시점·릴리즈 범위 등 최신 사용자 결정.

**main pull → 로컬 merge/충돌 해결 → 최종 병합 결과 검증 → 인수인계 갱신·최종 변경 확인 → 파일·staged diff·추적 파일·전송 전체 이력/blob·산출물의 비밀정보 점검 → 승인된 origin push** 순서입니다. 원격 main이 바뀌면 다시 통합하고 관련 검증·검사를 갱신합니다. force/reset으로 덮어쓰지 않습니다.

원본 MD/PDF·운영/보안 절차는 보존합니다. 실제 키·토큰·서명키·인증 파일·사용자 음성 원문·광범위 시스템 로그를 게시하지 않습니다. `.local`·빌드 출력·개인 설정은 각 환경의 로컬 자료입니다. 비밀값이 의심되면 값 대신 위치와 유형만 알리고 게시를 중단합니다. 자동 hook·스케줄러·다음 단계 진행 권한을 이 문서로 새로 만들지 않습니다.

## 2026-11-15 실제 음성·앱 재시작 수락 및 5+6 통합 착수

실제 사용자 녹음의 원음 재생과 STT 내용 일치를 사용자가 확인했다. 위치는 정보 없음으로 저장됐다. 앱 강제 종료 후 정상 진입에서 같은 STT·시각·상태가 복원됐고 원음 재생 상태도 확인했다. 원문/음성은 검증 보고서에 복사하지 않았다. 합성 한국어 ON_DEVICE 대조도 1/1 통과했으며 과거 무음 20초 timeout 두 건은 별도 실패로 보존한다.

최신 사용자 순서에 따라 5·6단계 전체 검증은 로컬 feature/05-06-integration의 조합 결과에서 수행한다. 기존 캡처 구현 최초 독립 검토와 최종 통합 수락은 남아 있다. 원음/사진/내비의 의미 연결은 7단계이며 UI 다듬기는 이번 범위가 아니다. 현재 main 병합·원격 push·Release 완료를 의미하지 않는다.
